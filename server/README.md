# myRPC-server

Программа-демон, которая принимает от `myRPC-client` имя пользователя и
команду BASH, проверяет пользователя по списку допущенных и выполняет
команду, возвращая клиенту её вывод.

Каждый запрос обслуживается в отдельном процессе. При завершении работы
демон сначала останавливает все рабочие процессы и лишь затем завершается
сам.

## Сборка

```sh
make            # собрать myRPC-server
make clean      # удалить объектные файлы и исполняемый файл
make deb        # собрать пакет myrpc-server_1.0.0_amd64.deb
```

Требования: `gcc`, `make`, `dpkg-dev` (для цели `deb`).

## Установка

```sh
sudo dpkg -i build/myrpc-server_1.0.0_amd64.deb
```

Пакет устанавливает:

| Путь | Назначение |
|---|---|
| `/usr/sbin/myRPC-server` | исполняемый файл демона |
| `/etc/myRPC/myRPC.conf` | конфигурация (порт, тип сокета, режим запуска) |
| `/etc/myRPC/users.conf` | список допущенных пользователей |
| `/lib/systemd/system/myRPC-server.service` | юнит systemd |

Оба файла в `/etc/myRPC` помечены как `conffiles`, поэтому при обновлении
пакета внесённые изменения не теряются.

## Конфигурационные файлы

`/etc/myRPC/myRPC.conf` — читается при запуске и по сигналу `SIGHUP`:

```
#comment
port = 1234
#socket_type = dgram
socket_type = stream
daemon = yes
```

| Параметр | Значения | Назначение |
|---|---|---|
| `port` | 1…65535 | порт, который слушает демон |
| `socket_type` | `stream`, `dgram` | транспорт: TCP или UDP |
| `daemon` | `yes`, `no` | запускаться демоном или оставаться в консоли |

`/etc/myRPC/users.conf` — список допущенных пользователей, по одному имени
в строке; строки, начинающиеся с `#`, игнорируются:

```
# допущенные пользователи
student
admin1
```

Пользователь, отсутствующий в этом списке, получает отказ, команда не
выполняется, факт отказа записывается в журнал.

## Аргументы командной строки

| Короткий | Длинный | Назначение |
|---|---|---|
| `-c` | `--config` | путь к конфигурации, по умолчанию `/etc/myRPC/myRPC.conf` |
| `-u` | `--users` | путь к списку пользователей, по умолчанию `/etc/myRPC/users.conf` |
| `-l` | `--log` | писать журнал в указанный файл вместо syslog |
| `-f` | `--foreground` | не уходить в фон (удобно при отладке) |
|  | `--help` | вывести справку |

## Запуск

Как служба:

```sh
sudo systemctl enable --now myRPC-server
systemctl status myRPC-server
sudo systemctl reload myRPC-server     # послать SIGHUP, перечитать конфигурацию
```

В консоли (для отладки):

```sh
sudo myRPC-server -f -l /tmp/myrpc-server.log
```

## Обрабатываемые сигналы

| Сигнал | Действие |
|---|---|
| `SIGINT` (Ctrl+C), `SIGTERM` | остановить рабочие процессы, затем завершиться |
| `SIGHUP` | перечитать `myRPC.conf` и `users.conf`; при изменении порта или типа сокета пересоздать сокет |
| `SIGCHLD` | снять завершившиеся рабочие процессы, запись в журнал |
| `SIGPIPE` | игнорируется, чтобы разрыв соединения клиентом не убивал демон |

Получение каждого сигнала записывается в журнал.

## Журнал

По умолчанию демон пишет в syslog с идентификатором `myRPC-server`:

```sh
sudo journalctl -t myRPC-server -f
sudo grep myRPC-server /var/log/syslog
```

С ключом `-l` журнал ведётся в обычном файле.

## Временные файлы

Вывод выполняемой команды собирается во временные файлы по шаблонам
`/tmp/myRPC_XXXXXX.stdout` и `/tmp/myRPC_XXXXXX.stderr`, которые создаются
функцией `mkstemps` и удаляются после отправки ответа. Имена созданных
файлов записываются в журнал.

## Безопасность

* команда выполняется только для пользователя из списка допущенных;
* команда запускается через `/bin/sh -c` в отдельном процессе, вывод
  перенаправляется в закрытые временные файлы;
* специальные символы в запросе экранируются на уровне протокола, поэтому
  кавычки и переводы строк не ломают разбор сообщения;
* права на `/etc/myRPC/users.conf` — `0600`, файл читает только root.
